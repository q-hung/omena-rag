Ask: three short transactions around one long unlocked stretch

Only the lease and the save touch the conversation row, and each is a short transaction. Everything slow (embedding, retrieval, the LLM call) runs with no transaction held. The save compares generation_token under FOR UPDATE, so a request whose lease went stale cannot overwrite the new holder. Any failure clears the lease and writes an error marker; the account facts are read through a read-only transaction and a database failure becomes a 503, never an empty result.
