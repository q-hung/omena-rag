Omena

How an employee question reaches the model: one request path, one background worker, one external dependency.

Primary path: Ask

  • SPA posts to /api/conversations with the omena_session cookie.
  • Route validates with zod, a service loads account facts from PostgreSQL.
  • RAG retrieves chunks (SQL access filter, vector or hybrid RRF) and builds the prompt.
  • LLM provider embeds the query and generates; output is validated before it is stored.

Trust boundaries

  • Client to API: session cookie, APP_ORIGIN check, auth hook on every route.
  • API to Gemini: key stays server side; no key means the labeled stub provider.
  • Worker to extract child: separate process, 256 MB heap, killed on timeout.
  • LLM output and uploaded documents are untrusted input.

Data and async

  • PostgreSQL holds accounts, conversations, chunks (pgvector + tsvector) and the RFP queue.
  • Worker claims KB versions first, then RFP questions; pnpm worker --once drains both.
  • Token budget is reserved before and reconciled after each paid call.
