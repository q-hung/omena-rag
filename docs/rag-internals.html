Overview

Two processes, one Postgres. Postgres is the queue, the lock manager, the vector store and the budget ledger. There is no Redis and no broker.

Prompt assembly facts

  • Account facts are never dropped. When the 6,000 token budget (chars ÷ 4) is exceeded, passages are removed from the tail until it fits. rag/prompt.ts
  • Employee text is wrapped in <untrusted> and the instructions say to ignore commands inside it. Passages are also declared data.
  • The model cites with [F#] and [S#]. normalise() resolves them, renumbers citations in order of first use, strips invalid ones (adds review reason invalid_citation_removed) and forces outcomes after two clarification rounds.
  • The facts snapshot (as_of) is stored on the answer, so the saved answer is reproducible even after the account changes.

Version state machine

Chunking

  • Target 500 tokens (chars ÷ 4). Markdown splits per section and keeps section.path as the heading; PDF splits per page and keeps page_number.
  • Oversized sections split on blank lines, greedily packed; a single paragraph over the limit is hard-cut every 2,000 chars.
  • Embedding input is title: {heading} | text: {chunk} for documents and task: search result | query: {q} for queries. Asymmetric formats are part of the contract: changing them requires re-embedding everything.
  • Each chunk row stores embedding_model. Retrieval filters on it, so a model swap does not mix vector spaces; old chunks simply stop matching until re-indexed.

Five distinct mechanisms. Know which one protects which invariant.

Generation lease: T1 / work / T2

T1 (txn):  SELECT ... FOR UPDATE conversation
           assertNotSaved, assertGenerateQuota
           UPDATE conversations SET token=$new, started=now()
             WHERE id=$id AND (token IS NULL OR started < now() - 2min)   -- 0 rows = 409
work:      snapshot, embed query, retrieve, build prompt, LLM   (NO txn, 90 s deadline)
T2 (txn):  SELECT generation_token ... FOR UPDATE
           if token != mine  -> 409 LOCK_TAKEN (discard result)
           INSERT answers, answer_sources; UPDATE ... SET token=NULL
on error:  clearLock WHERE token = mine   (token-guarded, cannot clear someone else's)
Ordering gotchaThe lease TTL is 2 minutes and the request deadline is 90 s. That margin is the whole safety argument: a live holder should always finish or fail before its lease can be stolen. If you raise the deadline, raise the TTL first.

Save-time stale-source check

Saving a reviewed answer takes FOR UPDATE on the conversation, then FOR SHARE on every cited document in id order (a consistent order avoids deadlocks with concurrent activations), then runs one query: any cited chunk that is missing, belongs to an archived doc, or is no longer the document's active version raises SOURCE_STALE. The RFP side exposes the same check read-only as sourceStale.

Worker loop order

for (;;) {
  sweepAbandonedReservations()   // reserved > 10 min → error/abandoned
  failStaleProcessing()          // versions
  failStaleQuestions()           // questions
  v = claimVersion();  if (v) { processVersion(v); continue }   // indexing wins
  q = budgetDay === today ? null : claimQuestion()
  if (q) { if (processQuestion(q)) budgetDay = today; continue }
  if (once) return; sleep(2s)
}
  • Indexing has priority over RFP answers: new KB content lands before answers that should cite it.
  • After budget_reached the worker stops claiming questions until the next UTC day. Versions still index (embedding is cheap and also budgeted).
  • pnpm worker --once drains both queues and exits. Tests use runWorker({ once: true, rfp: { provider } }).

Retrieval

One SQL access filter, two modes. Default is vector; hybrid is opt-in via RETRIEVAL_MODE.

FROM document_chunks c
JOIN document_versions v ON v.id = c.version_id
JOIN documents d ON d.active_version_id = v.id AND d.archived_at IS NULL
WHERE c.embedding_model = $model
ORDER BY c.embedding <=> $query_vec  LIMIT 8      -- cosine; score = 1 - distance
  • vector: top 8 by cosine, drop anything under RETRIEVAL_MIN_SCORE (0.5 live). Empty result is a valid outcome and drives insufficient_evidence.
  • hybrid: vector top 20 (floor applied) + lexical top 20 (websearch_to_tsquery with & rewritten to |, ranked by ts_rank_cd over the generated search_tsv GIN column), fused with RRF, top 8. Lexical-only hits bypass the floor. Fused scores are on the RRF scale, not cosine, so they are not comparable with vector scores in answer_sources.score.
  • stub (tests): token overlap over all eligible chunks, no floor. Not a performance model.
Scale ceilingNo vector index exists (no HNSW or IVFFlat in the migrations), so every query is an exact scan of 768-d vectors, filtered by join. Fine at demo size. Add HNSW when chunk count reaches the tens of thousands, and re-check that the filter join still lets the planner use it (post-filtering can return fewer than 8 rows).

Budget and quota

Every embedding and generation call goes through paidAttempt: reserve, call, reconcile.

reserve():   (txn)
  [generate attempt 1] pg_advisory_xact_lock(employee) ; count today's attempt-1 rows < 50
  INSERT budget_days(day, spent) VALUES (today, est)
    ON CONFLICT (day) DO UPDATE SET spent = spent + est
    WHERE spent + est <= DAILY_BUDGET          -- 0 rows returned = budget_reached
  INSERT provider_calls(status='reserved', estimated_cost)
fn():        network call, NO txn
reconcile(): (txn) status=ok|error; if usage known: spent += (actual - estimate)
sweep():     reserved > 10 min → error/abandoned   (budget NOT refunded: conservative)
  • The cap check is inside the upsert's WHERE, so it is atomic. No read-then-write race.
  • The estimate is pessimistic (input chars ÷ 3 plus MAX_OUTPUT_TOKENS), so a call can be rejected while real spend is below the cap.
  • Quota counts only attempt = 1 generate rows. Retries are free to the employee; failure markers are written with attempt = 0 so they never count.
  • Retries: up to 2 retries with jittered exponential backoff (200 ms base, 8 s cap), only for 429, 5xx, timeouts, and never past the 90 s deadline. Each retry is its own paid attempt and its own reservation.
  • Days are UTC. budget_days rolls over by key, no cron needed.

Failure modes

What breaks in production, how it shows up, and what to check. Items marked ceiling are known limits of the current design, not bugs to hotfix.

SymptomCauseCheck / action
Version stuck processingWorker died mid-index.Sweeper fails it after 10 min with "Indexing timed out."; retry from the KB UI (retryVersion, latest version only).
Version failed: "No page has a text layer"Scanned PDF. OCR is unsupported by design.Re-export with a text layer. Blank-page warnings are not persisted.
"Extraction timed out" / memory limitParser runs in a child process: 60 s wall, --max-old-space-size=256, empty env, SIGKILL.The worker survives a hostile PDF. Do not move extraction in-process.
409 INDEXING_IN_PROGRESSSecond upload of a document whose previous version is queued/processing.Expected. One in-flight version per document.
409 DUPLICATE_HASHSame sha256 as the active version.Expected. Dedup against the active version only, not older ones.
409 GENERATION_IN_PROGRESSLease held and under 2 min old.Wait. If it never clears, the holder crashed; it frees itself after the TTL.

Known ceilings and sharp edges

Indexing has no zombie guardThe sweeper marks a slow-but-alive version failed, but nothing stops that worker from later calling activateVersion, which flips the row to ready. Questions have a token for this; versions do not. Consequence is benign today (the result is valid), but a user may have already hit Retry, giving two workers indexing the same version. Chunk inserts are protected by the (version_id, chunk_index) unique key and the delete-then-insert inside the document lock, so the outcome is last writer wins, not corruption.
Pre-activation delete is outside the txnprocessVersion deletes the version's chunks before extraction, then activateVersion deletes again inside the lock. The first delete only matters for retries; retrieval never sees a non-active version's chunks anyway.
Activation only moves forwardA version becomes active only if its number is higher than the current active one. Out-of-order completion (v3 finishes before v2) leaves v3 active. Rollback to an older version is not supported by this path.
One question at a time per workerNo intra-worker parallelism. Throughput scales by running more workers (safe thanks to SKIP LOCKED), bounded by provider rate limits and the daily budget.
Embedding batch ceilingEMBED_BATCH_SIZE = 100 matches the provider's per-request cap. Each batch has a 60 s deadline and its own reservation, so a large document costs several ledger rows.
Dates and moneyAll UTC through one validated utc(); money is integer minor units. The frontend keeps a native-Date copy of the formatters, and both outputs must stay identical.
